# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

FastAPI backend for an AI expense tracker. Users sign in with Google or Notion and log expenses or income from receipt images, free text, or voice recordings. Gemini extracts a draft the user reviews and edits before it is saved; each user's own Google Sheet or Notion database is the system of record (the default comes from the login provider). Postgres stores only users, per-user storage config (encrypted credentials, target ID, status), and image-dedup hashes; the server never stores financial records. Prompts handle Burmese, English and Thai input.

## Commands

Dependencies are managed with `uv` (Python >= 3.12, see `.python-version`).

```bash
uv sync                                   # install deps (incl. dev group: pytest)
uv run uvicorn main:app --reload          # run dev server (Swagger at /docs)
uv run pytest -q                          # tests (SQLite in memory + FakeGoogle; no network)
uv run pytest tests/test_sheets_storage.py::test_columns_reordered   # single test
uv run alembic upgrade head               # apply migrations
uv run alembic revision --autogenerate -m "msg"   # new migration from models/
```

`tests/conftest.py` sets test env vars before any app import, so tests never use the real `.env` secrets or database. `tests/test_provisioning_concurrency.py` needs real Postgres: it runs only when `TEST_DATABASE_URL` is set (it refuses to run against `DATABASE_URL` and uses a throwaway schema). No linter or formatter is configured.

Deployment is Render (`render.yaml`): `uv sync --frozen`, then `uvicorn main:app --proxy-headers`. The env vars listed there predate the multi-user work (`NOTION_TOKEN`/`NOTION_DATABASE_ID` are no longer read).

## Configuration (`.env`)

- `core/config.py` (`Settings`): `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` (**required**: startup fails if missing or empty), `GEMINI_API_KEY`, `REDIRECT_URI` (Google OAuth callback), `NOTION_CLIENT_ID` / `NOTION_CLIENT_SECRET` / `NOTION_REDIRECT_URI`, `FRONTEND_URL` (both login callbacks redirect to `{FRONTEND_URL}/auth/callback`), `DATABASE_URL`, `JWT_SECRET`, `SESSION_SECRET`, `CREDENTIALS_ENCRYPTION_KEY` (a Fernet key), `COOKIE_SECURE`, `ALLOWED_ORIGINS` (comma-separated CORS list).
- `DATABASE_URL` is a plain `postgresql://` URL. `core/db.py` rewrites it to `postgresql+asyncpg://`, strips `sslmode`/`channel_binding`, and forces SSL with `statement_cache_size=0` (pgbouncer-safe). Alembic (`migrations/env.py`) uses the raw URL with sync psycopg2. Keep both paths working when you change the URL format.

## Architecture

Layering: `routers/` → `core/dependencies.py` (all DI wiring) → `services/` → `models/` (SQLAlchemy) and `schemas/` (Pydantic). `repositories/` is empty. Services are built per request through FastAPI `Depends` factories in `core/dependencies.py`. New services should be wired there, not built inside routers. Storage domain errors are mapped to typed JSON bodies (`{"code": ...}`) in `core/errors.py`.

**Auth.** Authlib OAuth for Google (`/api/auth/google/login` → `/callback`) and Notion (`/api/auth/notion/login` → `/callback`). Starlette `SessionMiddleware` holds OAuth state (and a one-shot Google re-consent flag). Both callbacks set an HS256 JWT (7-day TTL) in an httpOnly `access_token` cookie (`core/cookies.py`) and redirect to the frontend; `core/security.get_current_user` reads that cookie. The `expense`, `entries`, `export`, `settings` and `storage` routers require it router-wide.

**Account linking.** `GET /api/auth/google/connect` / `GET /api/auth/notion/connect` (signed in; browser navigation) put a link intent (`{provider, user_id}`) in the Starlette session and reuse the normal OAuth callbacks, so no extra redirect URIs. A callback with an intent for its provider re-checks that the cookie user is the one who started it, calls `AuthService.connect_google` / `connect_notion` (sets `users.google_sub` / `notion_user_id`, stores credentials; Google also provisions the spreadsheet and does the one-shot re-consent), keeps the current session and redirects to `{FRONTEND_URL}/settings?connect=google|notion&status=ok|account_in_use|needs_permission|provisioning_failed|error`. An identity that belongs to another account (or a second identity of the same provider) → `account_in_use`; accounts are never merged. `/login` clears a leftover intent. After linking, signing in with either provider reaches the same account.

**Sessions (signed-in devices).** Each login inserts a `user_sessions` row (`services/auth/session_service.start_session`) and the JWT carries its id as `sid`. `get_current_user` rejects a token whose session is missing, revoked or expired (tokens without `sid` too), sets `request.state.session_id`, and bumps `last_seen_at` at most every 5 minutes. The row keeps a device name parsed from the User-Agent by regex and a masked IP (`203.81.x.x`, `services/auth/client_info.py`); the full IP and any location are never stored (no GeoIP). `GET /api/auth/sessions` (current first), `DELETE /api/auth/sessions/{id}` (404 for others' / unknown, 400 for the current one), `POST /api/auth/sessions/revoke-others`; `/logout` revokes the current session. Starting a session deletes the user's ended rows.

Google requests `openid email profile drive.file` with `access_type=offline` (`core/oauth.py`). `drive.file` (non-sensitive) covers every Sheets/Drive call on files the app created; don't add the sensitive `spreadsheets` scope. `AuthService.login_with_google` upserts the user, stores credentials via `services/google/credentials.py` (keeps the old refresh token when Google omits one), then provisions the spreadsheet; provisioning failures never fail the login. `get_google_access_token` refreshes expired access tokens on use.

**Per-user storage.** `UserStorageConfig` holds one row per (user, provider): Fernet-encrypted credentials (`core/crypto.py`), `target_id` (Notion database ID or spreadsheet ID), and `storage_status` (`none | provisioning | ready | failed | needs_permission | schema_broken | missing`, constants in `constants/storage_status.py`). `get_storage_service` routes by `user.default_storage_provider` and raises `StorageNotReadyError` (409 `storage_not_ready`) unless that row is `ready`. `PUT /api/v1/storage/default {"provider"}` (`StorageConfigService.set_default_provider`) switches it, only to a provider whose row is `ready` (else that same 409); records are never copied, so history/insights show only the current provider. Everything implements `StorageStrategy` (`insert_many`, `get_all`). There is no server-side backup: a failed write raises `StorageWriteError` (502 `storage_write_failed`) and the client retries.

- **Notion**: Notion login stores the OAuth token only (`storage_status` stays `none`); the database is created after the user confirms. `GET /api/v1/storage` reports the Notion row's `status` even without a `target_id`, `GET /api/v1/storage/notion/pages` lists pages shared with the integration, and `POST /api/v1/storage/notion/setup {parent_page_id?}` (`services/notion/provisioning.py`, same lease as Sheets via `services/storage/user_storage.claim_provisioning`) reuses a usable `target_id` or creates the database under that page (default: the first shared page). No shared page / no access → `needs_permission`. `PUT /api/v1/storage/notion` (pasted integration token) still finds or creates it directly. Property mapping by display name is in `services/notion/property_config.py`.
- **Google Sheets** (`services/google_sheets/`, Google calls in `services/google/google_api.py`, an async httpx client):
  - `provisioning.py`: verify the stored file via Drive (Sheets still serves trashed files) → claim with a compare-and-set on `storage_status` (2-minute lease, so concurrent logins create one file) → reuse a file tagged with appProperty `app=ai-expense-tracker` → else create it. `POST /api/v1/storage/provision` re-runs this.
  - `schema.py` is the single source of the column layout (`FIELDS`: required `id/date/type/amount`, optional `category/description/currency/amount_thb/amount_mmk/amount_usd/payment_channel/source`) and the setup requests. `amount_thb/mmk/usd` are derived: the amount again, only in the column of its currency (so users can `SUM` per currency); readers ignore them. `BACKFILL_FIELDS` (`currency` and the three amount columns) are optional columns that older sheets get added on the next `insert_many` or `repair()`; their absence is never `schema_broken`. The same backfill re-applies the dropdowns in `REVALIDATED_FIELDS` (`payment_channel` = `Cash|Bank`, `source` incl. `manual`) on existing columns.
  - `google_sheets_storage.py`: columns are located **only** via Developer Metadata (`et_sheet` on the tab, `et_field` on each column), never by header text, column letter, tab title or row number; all Sheets calls use `sheetId`/gridRange. Reads use a per-user `TTLCache` of the mapping; writes always re-resolve. Records are addressed by the UUID in the `id` column. `repair()` (`POST /api/v1/storage/repair`) re-adds missing required columns or the tab. `record_url()` links to the saved row.
- **Notion** pages carry `Type` and `Currency` selects; databases created before them get the missing ones on the next write (`BACKFILL_PROPERTIES`).

**Extraction (strategy pattern).** `ImageExtractionStrategy`, `TextExtractionStrategy`, and `AudioExtractionStrategy` are ABCs. `GeminiExtractor` implements all three. Each returns **one** entry for the given `entry_type` (`expense|income`), or `None` when there is no usable amount (audio also returns the transcript). Prompts and JSON parsing live in `services/extraction/gemini_extractor.py`. The model name is in `constants/ai_models.py`; categories per type (fallback `"General"`) are in `constants/categories.py` (`CATEGORIES_BY_TYPE`); channels (`Cash|Bank`) in `constants/payment_channels.py`. Gemini returns `null` for a currency or channel it can't tell. "Today" is Bangkok time (`core/clock.py`). The Gemini client calls are synchronous inside `async` methods.

**Currency.** Every record has `currency` (`THB | MMK | USD`, `constants/currencies.py`); amounts are stored as entered and never converted or summed across currencies. Gemini returns a currency or `null` (`_currency()` drops anything unsupported); `EntryDefaults` (`services/entries/entry_defaults.py`) fills `null` from `users.default_currency` and tags `currency_source` (`detected | default`, response-only). Saving never changes the setting. Storage readers default a missing value to `THB` (Sheets: no Currency column/blank cell; Notion: no `Currency` select, added on the next write). `GET /api/v1/expense?currency=` filters by currency.

**Settings.** `GET /api/v1/settings` / `PATCH /api/v1/settings` (`routers/settings.py`, `services/settings/`) read and change `default_currency`, `default_payment_channel` (`Cash|Bank`) and `week_start` (`monday|sunday`) on `users`. PATCH changes only the fields sent; unknown fields, `null` or values outside the lists → 422. `week_start` sets where Insights weeks start.

**Export** (`routers/export.py`, `services/export/exporter.py`). `GET /api/v1/export?format=csv|xlsx` downloads every entry matching `date_from`/`date_to`/`currency`/`type` (omitted type = expenses and income) via `get_all`; `GET /api/v1/export/count` returns `{"count"}` for the same filters. CSV is UTF-8 with a BOM (Excel shows Burmese/Thai); xlsx uses openpyxl. Amounts are written as stored.

**Insights** (`routers/insights.py`, `services/insights/`). `GET /api/v1/insights?period=week|month|year|custom&date_from&date_to&currency&months&refresh` returns everything the Insights page shows for one currency (default `users.default_currency`): totals with `change_pct` vs the same days of the previous period (custom: the equal-length range before), chart buckets (day / calendar week from `week_start` / month, clipped to the period), categories per type, payment channels (expenses; free-text/null → `Other`), `highlights` (structured facts: `category_change`, `ratio`, `biggest_bucket`; the frontend words them) and a `months`-long monthly report. `periods.py` (date math) and `aggregate.py` (sums) are pure. Sums use raw floats, then round (MMK 0 dp, else 2); percentages are `null` when the base is 0. Records come from `services/storage/record_cache.py`: one unfiltered `get_all` per user, kept in a `TTLCache` (5 min) tagged with `(provider, target_id)`, cleared by `EntryService.on_saved` after a save and bypassed by `refresh=true`. The cache is per process and used only by insights and the dashboard.

**Dashboard** (`routers/dashboard.py`, `InsightsService.dashboard`, `aggregate.build_dashboard`). `GET /api/v1/dashboard?period=week|month|year` is Home, always in `users.default_currency`. It returns `totals` (same rules as insights), the period's expense `categories`, one `insight` (the `category_change` highlight, else `ratio`, else null) and `spending_flow`: the last 7 days by day whatever the period (expense and expense-entry count per day, `peak` day, change vs the 7 days before). It shares the records cache with insights.

**Delete account.** `DELETE /api/auth/me` → `AuthService.delete_account`: best-effort Google token revoke (`revoke_google_token`; failures are logged, never block), then explicit deletes of the user's `expenses_dedup`, `user_sessions` and `user_storage_config` rows and the user; clears the cookie (204). The user's Sheet / Notion data is never touched.

**Listing.** `GET /api/v1/expense` and `GET /api/v1/income` (`routers/expense.py`) share one storage and differ only in the `entry_type` they put in the `EntryFilter`. Query params: `page` (1-based), `page_size` (≤ 100), `search` (case-insensitive substring of description or category), `date_from`/`date_to` (inclusive; reversed → 422), `category` (case-insensitive exact), `currency`. `get_all(filters)` returns **every** match, newest first; `services/storage/pagination.paginate` slices it into `EntryPage` (`content, page, pageSize, totalElements, totalPages, first, last`). `services/storage/filters.matches` is the single filter rule set: Sheets applies it in memory; Notion pushes type/currency/date into the query (sorted by Date, following `next_cursor` to the end), then applies `matches` too. Records with no type count as `expense`; a Notion database without a `Type` property has no income.

**Entries: review before save** (`services/entries/entry_service.py`, `routers/entries.py`). Adding an entry is two calls:
- `POST /api/v1/entries/extract` (multipart: `type`, `mode` = `text|slip|voice`, `text` or `file`, optional `duration_seconds`) returns `{"status": "draft", "draft": {...}}`, `{"status": "duplicate"}` (slip hash already in `expenses_dedup`; Gemini is not called) or `{"status": "unreadable", "mode": ...}`. It **never writes** storage or the DB. Missing values are defaulted (currency and channel from the user's settings via `EntryDefaults`, tagged `currency_source` / `payment_channel_source` = `detected | default`; category not in the type's list → `General`). The draft lives only on the client.
- `POST /api/v1/entries` takes the reviewed `EntryCreate` (`source` may be `manual` with no extract call), validates it (category must match the type, MMK whole numbers, THB/USD ≤ 2 decimals → 422), claims `slip_hash` in `expenses_dedup` **before** writing (unique constraint → 409 `duplicate_entry`, so two tabs can't save the same slip), writes one record with `insert_many`, releases the claim if the write fails. Returns 201 with the entry and `storage_url`.

## Database / migrations

Models subclass `models.base.Base` and must be imported in `models/__init__.py` so Alembic autogenerate can see them. Datetime columns use `DateTime(timezone=True)` with UTC defaults. Uniqueness is enforced in the DB: `(user_id, provider)` on storage config and `(user_id, hash)` on dedup; concurrent first logins rely on it (savepoint insert + `IntegrityError` re-select). `data/app.db` is a leftover SQLite file; the app uses Postgres.

API docs for the frontend are in `docs/API.md` and `docs/AUTH.md`, which are gitignored.
